? Frequently Asked — Quick Prep
What is Change Detection and how does OnPush work? ▼
Angular's change detection checks if the UI is in sync with component data. By default it checks every component on every event. OnPush tells Angular to only re-render a component when: (1) an @Input reference changes, (2) an event inside the component fires, or (3) an Observable emits and you use async pipe. This dramatically reduces checks in large apps.
@Component({ changeDetection: ChangeDetectionStrategy.OnPush }) // Now Angular skips this tree unless input ref changes or markForCheck() is called
Difference between switchMap, mergeMap, concatMap? ▼
switchMap: cancels the previous inner observable when a new value comes — perfect for search/typeahead.
mergeMap: subscribes to all inner observables simultaneously — good for parallel HTTP calls.
concatMap: queues and processes one at a time — good for ordered operations.
// Search: use switchMap (cancel stale requests) this.search$.pipe( debounceTime(300), switchMap(term => this.api.search(term)) )
How do you prevent memory leaks in Angular? ▼
Use takeUntil with a destroy$ Subject, or the new takeUntilDestroyed() in Angular 16+. Always unsubscribe from Observables that don't complete automatically (Router events, fromEvent, interval, BehaviorSubject).
private destroy$ = new Subject<void>(); ngOnInit() { this.data$.pipe(takeUntil(this.destroy$)).subscribe(); } ngOnDestroy() { this.destroy$.next(); this.destroy$.complete(); }

◎ Why This Structure?
core/
Imported ONCE in AppModule. Services here are singletons. Never import CoreModule in feature modules — use forRoot() pattern.
shared/
Re-exported from every feature that needs it. Only dumb, reusable components go here — no business logic.
features/
Each feature is a lazy-loaded module. Separate bundles = faster initial load. Each has its own routing, components, and local state.
store/
NgRx slice per feature. Selectors memoize derivations. Effects isolate side effects (HTTP calls) from components.

switchMap — cancel & switch ▼
Cancels the previous inner observable when a new source value arrives. Perfect for search/typeahead where you only want the latest API response.
searchTerm$.pipe( debounceTime(300), distinctUntilChanged(), switchMap(term => this.apiService.search(term)) // ← previous request cancelled ).subscribe(results => this.results = results);
mergeMap — parallel execution ▼
Subscribes to all inner observables simultaneously. Use when order doesn't matter and you want parallel HTTP calls.
merchantIds$.pipe( mergeMap(id => this.apiService.getMerchant(id)) ).subscribe(merchant => this.merchants.push(merchant));
BehaviorSubject vs Subject ▼
BehaviorSubject holds a current value and emits it immediately to new subscribers. Subject emits only future values. Use BehaviorSubject for shared state (user session, permissions).
// Service private user$ = new BehaviorSubject<User | null>(null); currentUser$ = this.user$.asObservable(); setUser(u: User) { this.user$.next(u); } // Component — gets current value immediately on subscribe this.authService.currentUser$.subscribe(u => this.user = u);
debounceTime + distinctUntilChanged for search ▼
Prevent API hammering. debounceTime waits for user to stop typing. distinctUntilChanged skips identical consecutive values.
this.searchControl.valueChanges.pipe( debounceTime(400), // wait 400ms after last keystroke distinctUntilChanged(), // only emit if value actually changed switchMap(v => this.api.search(v)) ).subscribe(...);
NgRx Data Flow ▼
Component → dispatch(Action) → Reducer (pure fn, new state) → Store → Selector → Component. Side effects (HTTP) live in Effects, which dispatch new actions.
// Action export const loadMerchants = createAction('[Merchant] Load'); export const loadMerchantsSuccess = createAction('[Merchant] Load Success', props<{merchants: Merchant[]}>()); // Effect loadMerchants$ = createEffect(() => this.actions$.pipe( ofType(loadMerchants), switchMap(() => this.api.getMerchants().pipe( map(merchants => loadMerchantsSuccess({ merchants })) )) ));
Selectors — memoized derived state ▼
Selectors compute derived data from store. createSelector memoizes — it only recomputes if input slices change. Combine multiple selectors with createSelector.
const selectMerchantState = (state: AppState) => state.merchant; const selectAllMerchants = createSelector(selectMerchantState, s => s.merchants); const selectActiveMerchants = createSelector(selectAllMerchants, merchants => merchants.filter(m => m.status === 'active'));
Default vs OnPush Change Detection ▼
Default: Angular walks the entire component tree and checks every binding on every change (click, timer, HTTP). Expensive in large apps.
OnPush: Angular only checks the component when an @Input reference changes, an internal event fires, or an async pipe emits. Can reduce checks by 10–100x.
@Component({ changeDetection: ChangeDetectionStrategy.OnPush }) // IMPORTANT: mutating arrays/objects won't trigger update // You must create new references: this.merchants = [...this.merchants, newMerchant]; // ✓ new ref this.merchants.push(newMerchant); // ✗ same ref, won't update
Angular Signals (16+) — reactive primitives ▼
Signals are reactive values that notify consumers when they change. Angular 16+ introduces signal(), computed(), and effect() as a simpler alternative to RxJS for local state.
// Component count = signal(0); doubled = computed(() => this.count() * 2); increment() { this.count.update(v => v + 1); } // Template // <div>{{ count() }} — {{ doubled() }}</div> // Effect (runs when signal changes) effect(() => console.log('count is', this.count()));
Signals vs RxJS — when to use which? ▼
Use Signals for local component state, derived values, and simple reactivity. Use RxJS for async streams, HTTP calls, event handling, and complex operators (debounce, switchMap). They interop via toSignal() and toObservable().
// Convert Observable to Signal import { toSignal } from '@angular/core/rxjs-interop'; merchants = toSignal(this.store.select(selectAllMerchants));
Functional Route Guards (Angular 15+) ▼
Class-based guards are deprecated in Angular 15+. Use functional guards with inject().
// auth.guard.ts export const authGuard: CanActivateFn = () => { const auth = inject(AuthService); const router = inject(Router); return auth.isLoggedIn() ? true : router.createUrlTree(['/login']); }; // RBAC guard export const roleGuard = (role: string): CanActivateFn => () => { const permission = inject(PermissionService); return permission.hasRole(role); };
HTTP Interceptor — token + loading state ▼
Intercept every outgoing HTTP request to add auth header and track loading state.
export const tokenInterceptor: HttpInterceptorFn = (req, next) => { const auth = inject(AuthService); const loader = inject(LoaderService); const token = auth.getToken(); loader.show(); const authReq = token ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }) : req; return next(authReq).pipe(finalize(() => loader.hide())); };

JavaScript Core

Tricky concepts that separate seniors from juniors

1. Explain closures with a real example ▼
A closure is a function that remembers variables from its outer scope even after the outer function has returned. Angular services use closures implicitly through captured dependencies.
function makeCounter() { let count = 0; // captured in closure return { increment: () => ++count, get: () => count }; } const c = makeCounter(); c.increment(); c.increment(); c.get(); // 2 — count is still accessible
2. Event Loop — microtasks vs macrotasks ▼
JS is single-threaded. The event loop checks the call stack, then drains the microtask queue (Promises, queueMicrotask), then picks one macrotask (setTimeout, setInterval, I/O). Microtasks always run before the next macrotask.
console.log('1'); // sync setTimeout(() => console.log('4'), 0); // macrotask Promise.resolve().then(() => console.log('3')); // microtask console.log('2'); // sync // Output: 1, 2, 3, 4
3. Hoisting — var vs let/const ▼
var declarations are hoisted and initialized as undefined. let/const are hoisted but NOT initialized — accessing them before declaration throws ReferenceError (Temporal Dead Zone).
console.log(x); // undefined (hoisted) var x = 5; console.log(y); // ReferenceError: TDZ let y = 10;
4. Promises vs Observables ▼
Promises: single value, eager (execute immediately), not cancellable. Observables: multiple values over time, lazy (execute on subscribe), cancellable (unsubscribe), composable with operators. Angular's HttpClient returns Observables.
// Promise — fires immediately, one value const p = fetch('/api/data'); // already running! // Observable — lazy, multiple values, cancellable const obs$ = this.http.get('/api/data'); // NOT running yet const sub = obs$.subscribe(...); // now it runs sub.unsubscribe(); // cancel!
5. call, apply, bind — this context ▼
All three explicitly set the `this` context. call/apply invoke immediately (apply takes args as array). bind returns a new function with fixed `this`.
function greet(greeting) { return `${greeting}, ${this.name}`; } const user = { name: 'Arjun' }; greet.call(user, 'Hello'); // Hello, Arjun greet.apply(user, ['Hi']); // Hi, Arjun const boundGreet = greet.bind(user); boundGreet('Hey'); // Hey, Arjun
6. async/await vs Promises ▼
async/await is syntactic sugar over Promises. It makes async code look synchronous and is easier to read, especially with error handling. But avoid async/await in Angular templates — use async pipe with Observables instead.
// Promise chain fetchUser().then(u => fetchOrders(u.id)).then(o => render(o)); // async/await (cleaner) async function loadData() { const user = await fetchUser(); const orders = await fetchOrders(user.id); render(orders); }

Performance Optimization

What separates mid-level from senior Angular engineers

◉ Change Detection
OnPush everywhere — set ChangeDetectionStrategy.OnPush on every component. Angular skips components whose inputs haven't changed (by reference).

async pipe — use {{ data$ | async }} in templates instead of manual subscribe/unsubscribe. Auto-unsubscribes on destroy.

markForCheck() — call when you mutate state outside Angular's zone (3rd party libs, WebSockets).
◉ Large Data Tables
trackBy — tell Angular how to track list items. Without it, Angular re-renders every row on any change.
// template *ngFor="let m of merchants; trackBy: trackById" // component trackById(index: number, item: Merchant) { return item.id; // stable identity }
Virtual Scrolling — CDK ScrollingModule for 10k+ rows. Renders only visible rows.
◉ Memory Leaks
// Pattern 1: takeUntil (classic) private destroy$ = new Subject<void>(); ngOnInit() { this.data$.pipe( takeUntil(this.destroy$) ).subscribe(); } ngOnDestroy() { this.destroy$.next(); this.destroy$.complete(); } // Pattern 2: Angular 16+ (cleaner) import { takeUntilDestroyed } from '@angular/core/rxjs-interop'; this.data$.pipe(takeUntilDestroyed()).subscribe();
◉ Bundle Size
Lazy loading — every feature module should be lazy. Use loadChildren in routes.

Preloading strategy — use PreloadAllModules or custom strategy to preload on idle.

Tree shaking — import only what you need. Avoid barrel imports that pull in entire libraries.
{ path: 'merchant', loadChildren: () => import('./features/merchant/merchant.routes') .then(m => m.MERCHANT_ROUTES) }

Top 50 Questions

Angular (30) + JavaScript (20) with interview-style answers

Angular 30 Questions
Q1. What is the difference between module-based and standalone Angular? ▼
In module-based Angular, components must be declared in an NgModule. Standalone components (Angular 14+) use standalone: true and import dependencies directly. Angular 17 makes standalone the default. Standalone components simplify lazy loading and remove unnecessary NgModule boilerplate.
Q2. What is ViewEncapsulation and its types? ▼
Controls how CSS is scoped to a component. Emulated (default): adds unique attributes to CSS selectors, scoped to component. None: no encapsulation, styles are global. ShadowDom: uses native Shadow DOM for true isolation. Use None carefully as it pollutes global styles.
@Component({ encapsulation: ViewEncapsulation.OnPush })
Q3. Smart vs Dumb component pattern — explain and when to use? ▼
Smart (Container): knows about the store/service, fetches data, dispatches actions. Dumb (Presentational): receives data via @Input, emits events via @Output, no service injection. This separation enables reusability, easier testing, and allows OnPush on dumb components without worry.
Q4. What is Zone.js and why might you go zone-less? ▼
Zone.js patches async APIs (setTimeout, fetch, addEventListener) to notify Angular when to run change detection. Going zone-less (Angular 17+) improves performance: no monkey-patching, no unnecessary CD cycles. With Signals, you can opt out of zones entirely using provideExperimentalZonelessChangeDetection().
Q5. How do you share data between sibling components? ▼
3 approaches: (1) Parent via @Input/@Output: parent mediates. (2) Shared Service with BehaviorSubject: both components subscribe. (3) NgRx Store: dispatch action in one, select in other. For complex apps with many siblings, NgRx is the clean solution.
Q6. What is content projection and ng-content? ▼
Allows parent templates to inject HTML into a child component's template. Used heavily in shared UI components (modal, card, tabs). Multi-slot projection with select attribute allows multiple injection points.
<!-- card.component.html --> <div class="card"> <ng-content select="[card-header]"></ng-content> <ng-content select="[card-body]"></ng-content> </div>
JavaScript Top Questions
JS-1. Explain prototype chain ▼
Every JS object has a hidden __proto__ link to its prototype. When you access a property, JS looks up the chain until it finds it or reaches null. Classes are syntax sugar over prototypes.
function Animal(name) { this.name = name; } Animal.prototype.speak = function() { return this.name; }; const dog = new Animal('Rex'); dog.speak(); // 'Rex' — found on prototype
JS-2. What is the difference between == and ===? ▼
== performs type coercion before comparison. === checks value AND type (strict equality). Always use === in production code. Common trap: 0 == false is true, but 0 === false is false.
JS-3. What is debouncing vs throttling? ▼
Debounce: execute only after N ms of silence — search input. Throttle: execute at most once every N ms — scroll/resize. In Angular, use RxJS debounceTime/throttleTime instead of lodash helpers.
// Angular way this.searchInput.valueChanges.pipe( debounceTime(300) // wait for 300ms silence ).subscribe(v => this.search(v));
JS-4. Explain Promise.all vs Promise.allSettled ▼
Promise.all: rejects immediately if any promise rejects (fail-fast). Promise.allSettled: waits for all to complete/reject and returns an array of results — better for independent parallel calls.
// Dashboard: load all data in parallel, don't fail-fast const [merchants, txns] = await Promise.all([ this.api.getMerchants(), this.api.getTransactions() ]);

System Design

Frontend-focused — scalable SaaS Angular architecture

⊞ How to Design a Scalable Angular Dashboard
1. Shell + Feature module split
One AppShell component (sidebar, header) — stays loaded. Feature modules (dashboard, reports, users) lazy-loaded on demand. Each module owns its routes, state slice, and components.

2. State management layers
NgRx for global/shared state (auth user, permissions, notifications). Local signals/BehaviorSubject for component-local state (form values, UI toggles). Don't put everything in NgRx — that's an anti-pattern.

3. API communication layer
One ApiService per feature (not one giant ApiService). HTTP Interceptor handles tokens, loading states, error toasts globally. Use HttpContext to opt out of interceptors for public routes.

4. RBAC architecture
Store user permissions in NgRx. hasPermission directive controls element visibility. canActivate guard controls route access. Permission checks are synchronous — load permissions on login, cache in store.

5. Large data handling
Virtual scrolling (CDK) for 1000+ rows. Server-side pagination — never fetch all records. Debounced search with switchMap. Export large datasets via streaming (backend responsibility), show progress indicator in UI.
◈ Angular + Microservices
API Gateway pattern
Angular talks to ONE base URL. Backend gateway routes to merchant-service, payment-service, auth-service. Angular doesn't need to know about internal microservice boundaries.

BFF (Backend For Frontend)
A BFF layer aggregates multiple microservice calls into one UI-optimized response. Reduces over-fetching and multiple round trips from Angular.

Real-time data (WebSockets)
Use RxJS webSocket() operator. Connect once in a service, multicast with share() operator. NgZone.run() needed to trigger change detection from WS events if using zones.

Error boundaries
Global ErrorHandler class for uncaught errors. HTTP error interceptor for API failures. Feature-level error states in NgRx (loaded, loading, error).
// Feature state shape interface MerchantState { merchants: Merchant[]; status: 'idle' | 'loading' | 'success' | 'error'; error: string | null; }
